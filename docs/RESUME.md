# 简历与面试材料（wagent）

> 这个文件是「怎么写进简历 + 面试怎么讲」的素材库，数字都来自本仓库实测，
> 换真实数据后重跑评测即可替换。

## 一句话

**桌面微信 GUI Agent**：不 hook、不解密，用「截屏 + OCR」感知微信窗口，用「本地 7B/云端双模型 +
L0-L5 分层记忆 + 3B LoRA 风格模型」生成回复，用「三级安全执行器」落地，并配了规则指标 + LLM 评委的
A/B 评测与全链路 trace。

## 技术栈

Python 3.12 · asyncio/线程 · pydantic-settings · RapidOCR (ONNX) · win32/ctypes/PrintWindow ·
numpy · SQLite · bge-m3 向量检索 · Ollama 本地模型 · DeepSeek 云端 API · PyTorch + peft + bitsandbytes
（4bit QLoRA） · pytest/ruff/mypy · GitHub Actions

## 简历 bullet（按 STAR 写，数字可替换）

1. **感知层**：针对微信 4.x（Qt 自绘窗口）重构了非侵入式感知链路——用
   `PrintWindow(PW_RENDERFULLCONTENT)` 替代失效的窗口类名与 DDA 截图，实现**窗口被遮挡时仍可截屏**；
   用「气泡边界 + 颜色聚类」自动标定说话人配色（不再写死颜色），用「气泡左右边界一致性」合并多行消息，
   用「帧签名缓存」把空闲轮询从 ~10s/轮降到毫秒级。
2. **决策与执行**：设计 `BASELINE/IDLE/REPLYING/COOLDOWN` 触发状态机，用「尾部消息序列」区分
   「新消息追加 / 滚动 / OCR 抖动」，修复了启动即回旧消息、重复内容永久失效、误触发三类线上问题；
   执行层提供 `dry_run/review/send` 三级模式，点击前后各校验一次前台窗口并保存/恢复剪贴板，
   把「回复打进别的程序」的风险降为零。
3. **层级记忆**：构建 L0-L5 记忆体系（工作记忆/事件摘要/人物画像/事实卡/风格样本），
   事实卡强制携带**证据消息 id 与原文**（无证据直接丢弃，抑制幻觉）、同 key 自动 supersede；
   检索采用「相关性 + 时效 + 置信度」打分 + 本地 bge-m3 向量召回 + 时间新鲜度融合，
   使「3 个月前的工作话题」也能被正确想起。
4. **模型与评测**：本地 Qwen2.5-7B（0.66s/条）+ 云端 DeepSeek 双通道；用 228 条数据在 8GB 显存上
   完成 3B QLoRA（r=16, 4bit, 5.6 分钟, loss 3.84→0.76），A/B 评测显示**综合分 0.455→0.510、AI 味 0.21→0.00**，
   本地 7B 盲评 10 例 base 4 : LoRA 5（胜率 55.6%）。
5. **工程化**：200+ 单测（纯逻辑，不依赖模型/Windows GUI）、ruff/mypy 全绿、GitHub Actions CI、
   trace 全链路耗时落盘、一键脚本（采史/巩固/训练/评测），README 含架构图与实测指标。

## 关键工程难点（面试可展开）

| 难点 | 解法 | 代价/取舍 |
|---|---|---|
| 微信 4.x 换框架，旧类名/布局全失效 | 类名正则 + 进程名双重识别；比例布局改为「输入框自动定位反推消息区」 | 布局仍依赖视觉特征，大改版需重标定 |
| GPU 自绘窗口截不到 / 被遮挡截到别的程序 | PrintWindow 渲染整窗，实测与屏幕像素一致 | 少数窗口可能返回空白帧，需重试与降级 |
| 气泡颜色随版本/主题变化 | 几何自举（左右留白）+ 颜色聚类（彩色=我、比背景亮=对方）自动学习，按主题缓存 | 浅色主题下白气泡与背景对比度低，靠邻域投票兜底 |
| OCR 顺序/多行/时间戳噪声 | y 排序 + 气泡边界分组 + 时间戳继承 + 系统提示过滤 | 群聊/引用卡片暂不处理 |
| 触发时机 | 尾部序列状态机 + 「追加」判定 + 冷却/超时重试 | 极端滚动场景仍可能漏触发 |
| 长记忆 | 结构化事实卡（证据+有效期+冲突消解）+ 事件摘要 + 向量召回 | 事实抽取依赖 LLM，需抽样人工校验 |
| 8GB 显存 | 4bit QLoRA + 只存 adapter；评测分两段跑（生成→释放显存→评委） | 训练规模受限（3B/单卡） |
| 安全 | 默认 dry-run；三级模式；前台校验；剪贴板保护；金钱话题拦截 | 全自动模式仍有账号风险 |

## 面试高频问题（预备答案）

1. **为什么不用 hook / 协议 / UIA？** 合规与封号风险、微信 4.x 自绘导致控件树不可用、
   协议无公开接口。截图+OCR 最接近「读屏软件」，风险最低但依赖 UI 布局。
2. **怎么保证不乱回？** 状态机（基线/去重/冷却）+ 意图判定「不回复」+ 默认 dry-run。
3. **重复消息怎么处理？** 不用历史指纹，而用尾部序列：重复内容只要又追加了就能触发。
4. **记忆为什么不用纯向量？** 画像需要**可更新/可溯源**的结构化事实，向量只解决「相似」不解决「时效/冲突」。
5. **事实怎么防幻觉？** 强制 evidence_msg_id + 证据必须存在于输入 + 无证据丢弃 + 置信度阈值。
6. **为什么微调 3B 而不是 7B？** 8GB 显存下 QLoRA 3B 可训（7B 会 OOM），且知识走 RAG，微调只学口吻。
7. **怎么证明微调有用？** 规则指标（风格/AI 味/长度）+ LLM 盲评（交换 A/B 抵消位置偏差）。
8. **成本/延迟怎么优化？** 本地模型、帧缓存避免重复 OCR、记忆预算裁剪、prompt 长度控制。
9. **记忆怎么评测？** 构造「回忆类问题」测事实召回/冲突/过期误用（已留接口）。
10. **哪里做得不够？** 群聊/图片/表情包未支持；布局仍依赖视觉；真实数据规模训练待补；全自动模式仍有风险。

## 局限（诚实写进 README 的部分）

- 群聊、引用消息、图片/表情包未处理；
- 布局依赖视觉特征，微信大改版要重新标定；
- LoRA 目前是合成数据成就，真实风格需真实聊天记录重训；
- 全自动发送（`--mode send`）风险自负。
